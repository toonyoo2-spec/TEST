## 3. 기존 → 신규 매핑

### 3-1. 블로그 상태 매핑 (기존 단계 × 다음 담당/다음 액션/검증 상태 → 새 상태)

| 기존 | 새 상태 |
|---|---|
| 단계 1. 후보 준비 / 2. 주제 선택 (파이프라인 행이면) | 초안 작성 중 |
| 단계 3. 초안 검토 또는 다음 액션 = 내 확인 필요 또는 다음 담당 = 나 | 내 검토 |
| 단계 4. 블로그 제작·검증 + 다음 담당 = Claude (또는 검증 상태 = 수정 필요) | 수정 중 |
| 단계 4. 블로그 제작·검증 + 다음 담당 = Codex | 이미지·미리보기 작업 |
| 단계 5. 최종 승인 + 다음 액션 = 내 확인 필요 | 내 검토 |
| 단계 5. 최종 승인 + 다음 액션 = 시스템 대기 (승인됨) | 발행 대기 |
| 단계 6. 카드뉴스 제작·검증 / 7. 제작완료 + 발행 상태 ≠ 발행 완료 | 발행 대기 (카드 진행은 `카드뉴스` 칸으로) |
| 발행 상태 = 발행 완료 | 발행 완료 |
| 편성 구분 = Alter 이고 다음 담당 비어 있음 | 보류 |

**카드뉴스 칸 매핑**: 요청 전 → 안 함 / 제작 대기 → 제작 요청 / 제작 중·검수 필요·수정 반영 대기 → 제작 중 / 완료 → 완료.
**수정 메모** ← 블로그 수정 요청 (+ 이미지 재생성 내용 이어 붙임). **처리 기록** ← 피드백 처리 기록 + "\n---\n" + 이전 단계 기록 + "\n---\n" + Codex 검증 결과.

### 3-2. 카드뉴스 상태 매핑

| 기존 | 새 상태 |
|---|---|
| 단계 0. 제외 | 보류 |
| 단계 1. 주제 후보 | 주제 후보 |
| 단계 2. 주제 확정 | 제작 요청 |
| 단계 3. 원고 초안 / 4. 원고 검증 / 5. Figma 제작 | 제작 중 |
| 단계 6. 시안 검수 + 시안 검증 = 검증 필요 (다음 액션 = 내 확인 필요) | 내 검토 |
| 단계 6. 시안 검수 + 시안 검증 = 수정 필요 | 수정 중 |
| 단계 7. 발행 승인 | 업로드 대기 |
| 단계 8. 발행 완료 또는 인스타 게시물 있음 | 발행 완료 |
| 편성 구분 = Alter (단계 2 이하) | 보류 |

**수정 메모** ← 시안 수정 요청 (비어 있으면 원고 수정 요청).

### 3-3. 데이터 이전 방법 (행 수가 수십 건 수준이므로 Notion MCP로 처리)

1. 각 DB에 새 칸 추가: `상태`(status), `수정 메모`(text), 블로그에 `카드뉴스`(select)·`처리 기록`(text)·`미리보기`·`공개링크`(기존 칸 이름 변경으로 처리), 카드에 `블로그 미리보기` rollup. **기존 칸은 아직 지우지 않는다.**
2. Claude 세션(Notion 커넥터)에서 데이터 소스를 전체 조회(필요한 칸만) → 3-1·3-2 표대로 행마다 `상태`·`수정 메모`·`카드뉴스`·`처리 기록` 값을 계산해 notion-update-page로 기록. 한 번에 20행씩, 끝나면 readback으로 새 칸이 빈 행이 0건인지 확인.
3. 이름 변경: 블로그 미리보기→미리보기, 블로그 공개링크→공개링크, 블로그 수정 요청은 삭제 대상이므로 그대로 둠.
4. 뷰 교체(2장), 자동화 프롬프트 교체(4장), 가이드 수정(5장).
5. 1주일 운영 후 문제 없으면 기존 칸 삭제. 그 전까지는 "숨김"만.

## 6. 적용 순서와 되돌리기

### 적용 순서 (반나절, 자동화 중단 없이)

1. **동결**: 적용 당일 블로그·카드뉴스·디스패처 자동화 비활성화(update_trigger enabled=false). 주제선정·주간요약은 그대로.
2. **칸 추가**(3-3의 1단계). 기존 칸 유지.
3. **데이터 이전**(3-3의 2단계) + readback.
4. **뷰 교체**(2장). 기존 ✋ 뷰 4개는 필터만 수정, 옛 뷰는 삭제.
5. **웹훅 자동화 6개 트리거 교체**(4-5). Supabase 중계 함수는 변경 없음(속성 이름을 그대로 text에 담으므로).
6. **가이드 수정**(5장) — RUN.md v3 절 추가, job.json 치환, ENFORCED_GUARDRAILS 추가.
7. **프롬프트 교체**(4장) — 블로그·카드뉴스 v2는 Mac에서 기기 승인, 디스패처는 API로.
8. **드라이런**: 카드 1행을 `제작 요청`으로 바꿔 웹훅 → 큐 → 디스패처 → 카드 자동화가 그 행만 `제작 중`→`내 검토`로 올리는지 확인. 블로그 1행 `수정 중`으로 같은 확인.
9. **해동**: 자동화 3개 다시 활성화.
10. 1주일 뒤 기존 칸 삭제(3-3의 5단계).

### 되돌리기

- 10단계 전이면: 새 칸 숨기고 옛 칸 다시 표시, 옛 뷰는 Notion 휴지통에서 복원, 프롬프트는 `automation/prompts/01~05`(v2 버전)로 재교체, 웹훅 트리거 6개 조건을 4-5 표의 "기존" 열로 되돌림. 데이터는 옛 칸이 그대로라 손실 없음.
- 10단계 후면: Notion 데이터베이스 "속성 삭제 취소"는 30일 안에 휴지통에서 가능. 그 뒤는 `처리 기록`과 `상태`에서 역매핑(3-1·3-2 표 역방향)으로 복구.

### 적용하지 말아야 할 때

- 이번 주 발행 예정 행이 `내 검토`·`업로드 대기`에 3건 이상 몰려 있으면 발행 후로 미룬다.
- Codex 쪽 지침을 같은 날 못 바꾸면 미룬다. 블로그 `상태` 전환은 Codex와 Claude가 같은 값을 써야 돌아간다.
