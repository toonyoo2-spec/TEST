## 0. v1 대비 바뀐 점

1. **Codex 실행 코드를 1급 변경 대상으로 편입** (A). notion-pipeline/ 9개 파일 + 테스트 파일의 조건식·기록값 변경표(7장). LaunchAgent·중복 사본 처리 방침 포함.
2. **블로그 상태 9개로 재설계** (B1~B6). `수정 중`을 `수정 중(글)`(→Claude)과 `수정 중(그림)`(→Codex)으로 분리. `공개본 교체 대기` 추가(발행 후 수정분 4행 보존). `내 검토`는 Codex가 PC1728/mobile390 통과 후에만 설정. 사람 승인 = KWAN이 `내 검토 → 발행 대기`.
3. **카드 상태 7개로 축소**. `내 검토`를 없애고 Claude가 바로 `업로드 대기`로 올림(현행과 동일한 KWAN 조작 3가지: 고르기·수정 메모·링크). 번호 부여 시점 확정, 보류 시 번호 공백 허용.
4. **블로그 DB의 카드 칸 3개 → 카드 DB 단일 원천 + 양방향 relation·rollup 2개** (C1). `카드뉴스` select는 KWAN 요청용(안 함/제작 요청/연결됨)만 남김.
5. **발행 요일 칸 유지** (B7, blog-schedule.mjs 51행 보존). formula 전환은 하지 않음.
6. **`질문` 칸 신설** (B4). Codex·Claude가 사람 판단 질문을 쓰고 KWAN은 ✋ 뷰에서 봄.
7. **매핑을 행 단위 실데이터(F)로 검증**하고 우선순위를 `다음 담당/검증 상태 → 단계 → 발행 상태`로 재작성. 이상치 6종 처리 명시.
8. **큐 파일(blog-images-dev-queue.json) 상태 ↔ Notion 상태 대응표** (B8).
9. **가이드 파일 30여 개 판정표** (D): 현행 규칙은 `Automation/jobs/*/RUN.md` 현행 1절에만, 나머지는 포인터. 옛 절은 `Automation/archive/`로 이동(토큰 절감).
10. **자동화 재생성 절차와 Cowork 생성 프롬프트 4개 전문** (E1), 커넥터 최소 목록(E3), Notion 웹훅 6개 KWAN 클릭 순서(E4), 디스패처 체크를 view 조회로 유지하되 URL 자리표시(E5).
11. **적용 순서를 Codex 토큰 초기화(10/28) 기준으로 Day 0/1/2로 재편** (H + KWAN 추가 요구): 0단계 백업, 동결 대상 7개, Codex 예약·LaunchAgent 해제 시점, 07 글 10/29 공개와 CN-19 11/13을 대입한 적용 시점 제안, 롤백에 코드 복원 포함.
12. 토큰 절감: 자동화별 읽는 칸 고정(G1), RUN.md 현행 1절 재작성(G2), 블로그 정기 실행 월·목으로 축소(G3), 프롬프트 공통부는 인라인 유지가 더 싼 이유(G4).

- 일: 후보함에서 주제 2~4개 `선택됨` (블로그). 카드 후보 중 `제작 요청`.
- 월~금: ✋ 블로그 · 내 차례에서 DEV 미리보기 보고 `발행 대기` 또는 수정. ✋ 카드 · 내 차례에서 시안 보고 인스타 업로드 후 링크 붙이기, 또는 `수정 중` + 메모. `질문` 칸에 글이 있으면 답을 `수정 메모`에 적고 상태 선택.
- 그 외 전부 자동(Claude·Codex). 16시 푸시 알림이 밀린 것만 알려줌.
