## 1. 직접 하셔야 하는 것 (순서대로, 약 20분)

### ① Claude 데스크톱 앱에서 자동화 4개 편집
이 4개는 Mac의 Claude Desktop에서 실행되는 자동화라 프롬프트 변경에 기기 승인이 필요합니다. 데스크톱 앱 → 자동화(예약 작업) → 각 항목 편집:

| 자동화 | 프롬프트 파일 | 커넥터를 이것만 남기기 | 추가 설정 |
|---|---|---|---|
| [자동화 블로그] | `prompts/01_블로그.md` | Notion, Claude Code Remote | 트리거 추가 → API → 토큰 생성 (②에서 사용) |
| [자동화 카드뉴스] | `prompts/02_카드뉴스.md` | Notion, Claude Code Remote, Figma | **"세션 유지" 끄기** (가장 큰 절감), 트리거 추가 → API → 토큰 생성 |
| [자동화 주간요약] | `prompts/03_주간요약.md` | Notion, Claude Code Remote | 없음 |
| [자동화 주제선정] | `prompts/04_주제선정.md` | Notion, Claude Code Remote | 없음 |

커넥터 14개 → 2~3개로 줄이면 세션당 약 9만 토큰이 빠집니다.
비활성 상태인 "카드뉴스 파이프라인 자동 진행 (매일 6시)"는 앱에서 삭제해도 됩니다. (여기서 지우면 그 자동화가 만든 세션 기록도 같이 지워져서 제가 지우지 않았습니다.)

### ② API 토큰을 Supabase 시크릿에 입력
①에서 받은 URL과 토큰은 한 번만 표시됩니다. Supabase 대시보드 → kwan-tools → Edge Functions → Secrets:

| 이름 | 값 |
|---|---|
| `RELAY_KEY` | 아무 긴 임의 문자열 (Notion 웹훅 헤더에 같은 값 사용) |
| `ROUTINE_RELAY_URL` | [자동화 체크·웹훅중계]의 fire URL (`https://api.anthropic.com/v1/claude_code/routines/<id>/fire`) |
| `ROUTINE_RELAY_TOKEN` | [자동화 체크·웹훅중계]의 API 토큰 (`sk-ant-oat01-...`) |

> 2026-10-27 변경: 로컬(Mac) 자동화에는 API 트리거를 붙일 수 없다. 그래서 클라우드 자동화 **[자동화 체크·웹훅중계]**(trig_01RBbJFP3JTCg7Kxr8jFet7D, Haiku)가 웹훅을 받아 `fire_trigger`로 로컬 블로그·카드뉴스 자동화를 실행한다. 이 자동화는 원래 [자동화 체크]였고 이미 Claude Code Remote 연결을 갖고 있어서 그대로 쓴다(메시지가 "[웹훅]"으로 시작하면 중계만, 아니면 평일 16:07 정기 체크). API 트리거·토큰은 claude.ai/code → 자동화 → 이 항목 → 트리거 추가 → API에서 생성한다. ROUTINE_BLOG_*/ROUTINE_CARD_* 시크릿은 필요 없다.

이 대화에서 "시크릿 입력"이라고 하시면 입력창을 띄워 드립니다 (값은 저를 거치지 않고 대시보드로 바로 들어갑니다).

### ③ Notion 데이터베이스 자동화 만들기
각 DB → 자동화(⚡) → 새 자동화 → 트리거 설정 → 액션 "웹훅 보내기".
공통: 헤더 `x-relay-key` = RELAY_KEY 값. 보낼 속성은 아래 표의 것만 선택.

| DB | 트리거 | 웹훅 URL | 보낼 속성 |
|---|---|---|---|
| 블로그 파이프라인 | `다음 담당`이 `Claude`로 바뀜 | `...notion-to-claude?route=blog` | 제목, 단계, 다음 담당, 다음 액션, 블로그 수정 요청, 발행일 |
| 블로그 파이프라인 | `카드뉴스 작업 상태`가 `제작 대기`로 바뀜 | `...notion-to-claude?route=blog` | 제목, 단계, 카드뉴스 작업 상태, 발행일, 카테고리 |
| 블로그 후보함 | `선택됨`으로 바뀜 (상태 속성) | `...notion-to-claude?route=blog` | 제목, 주차, 상태 |
| 카드뉴스 DB | `단계`가 `2. 주제 확정`으로 바뀜 | `...notion-to-claude?route=card` | 제목, 단계, 발행일, 콘텐츠 출처, 카드뉴스(Figma) |
| 카드뉴스 DB | `시안 수정 요청`이 편집됨 | `...notion-to-claude?route=card` | 제목, 단계, 시안 수정 요청, 카드뉴스(Figma) |
| 카드뉴스 DB | `인스타 게시물`이 편집됨 | `...notion-to-claude?route=card` | 제목, 단계, 인스타 게시물 |

전체 URL 예: `https://kblwddlquwlvumhwkirl.supabase.co/functions/v1/notion-to-claude?route=blog`

### ④ 테스트
1. 블로그 DB 테스트 행의 `다음 담당`을 `Claude`로 바꾼다.
2. Supabase → Table Editor → `claude_relay_events`에 `status = fired` 행이 생기는지 확인. (`fire_failed`면 `detail` 칸에 이유가 있음)
3. Claude 앱에서 새 세션이 떠서 그 페이지만 처리하는지 확인.

### ⑤ 확인 후 주기 축소 (말씀하시면 제가 바꿈)
- [자동화 블로그] 평일 매일 → 월·목 (웹훅이 주 경로, 정기 실행은 안전망)
- [자동화 카드뉴스] 월·목 유지 (D 후보 등록, E 점검이 주기 작업)

## 2. 사용 습관 (토큰에 가장 크게 영향)

- **자동화가 만든 세션에서 대화하지 않기.** 질문·상담은 새 세션에서. 이번에 본 비용 중 블로그 $15, 주제선정 $8.6, 주간요약 $6.2는 대부분 실행된 세션 안에서 이어진 대화였습니다.
- **Notion에서 바꾸는 칸은 아래 표의 것만.** 나머지(단계 승격, 다음 액션, 검증 상태, 번호)는 Claude가 씁니다.

| DB | 내가 바꾸는 칸 | 뜻 |
|---|---|---|
| 블로그 파이프라인 | `다음 담당` → Claude (+ 필요하면 `블로그 수정 요청` 텍스트) | 이 글 고쳐라 |
| 블로그 후보함 | 상태 → `선택됨` | 이 주제로 써라 |
| 카드뉴스 DB | `단계` → 2. 주제 확정 | 이 주제로 만들어라 |
| 카드뉴스 DB | `시안 수정 요청` 텍스트 | 이렇게 고쳐라 |
| 카드뉴스 DB | `인스타 게시물` 링크 | 올렸다, 정리해라 |

## 3. 중계 함수 동작 요약

- Notion → `POST ?route=blog|card` (헤더 `x-relay-key`) → 페이지 ID·제목·속성을 한 줄 요약 → Claude 자동화 fire API 호출.
- 같은 페이지·같은 route가 180초 안에 다시 오면 실행하지 않고 `deduped`로 기록 (Notion 재시도 대비).
- Notion에는 항상 200을 돌려줘서 자동화가 일시정지되지 않음. 실패는 테이블에서 확인:

```sql
select fired_at, route, title, status, detail
from claude_relay_events order by fired_at desc limit 20;
```

- 소스: `automation/notion-to-claude/index.ts`, 테이블: `automation/notion-to-claude/migration.sql`
- Supabase 무료 한도(월 50만 호출) 대비 예상 사용량은 월 1천 회 미만.
